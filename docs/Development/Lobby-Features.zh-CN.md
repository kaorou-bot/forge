## 计时架构与修改边界

1. `HostedMatch` 在每局开始（含调度）前创建 `TimedGameDecisions`，结束时关闭。`GameLobby` 的时限是非序列化的房主配置；未修改 `GameLobbyData` 线上字段。
2. `PlayerOperationClock` 使用单调纳秒时间，只负责计费。`TimedGameDecisions` 是生产入口；早期 `PendingPlayerDecision` / `PlayerDecisionSession` 是仍保留测试的基础层，不是生产对局调度器。
3. `PlayerControllerHuman` 的选择入口和 `HumanCostDecision.decide` 建立请求上下文。`InputSyncronizedBase`、`WaitCallback`、桌面 `FThreads.callInEdtAndWaitChoice`、远程等待各持有独立 `WaitRegistration`；按身份关闭且幂等。FDialog 捕获具体等待的 ready 回调，旧窗口不能启动之后的计时。
4. 输入动作通过 `InputActionGate` 登记同步及已入队任务。处理期间父等待暂停，嵌套弹窗可单独计费；取消后先排空已经获准的动作，再让原等待栈处理出局。不能仅在游戏线程队尾投递判负，否则该线程仍被选择阻塞。
5. 定时器只取消等待，不并发修改 Game。原等待栈调用正常玩家离局逻辑；`PlayerDecisionFrame` 在施放、费用、结算、调度和宣攻/阻挡边界停止已失效的操作。费用失败不得转交别人付款；仍存在的其他玩家对象必须按规则委派合法必选选择，而不是返回假 null / 空列表。
6. `Game.onPlayerLost` 用独立处理中集合与在局玩家成员资格防重复清理，不能用 `hasLost()` 作为已经清理的标志：输掉结果在调用清理前已经设置。保留其他在局玩家、清除离局玩家的普通/冻结堆叠对象及法术力支付临时状态。
7. 能力协商利用原 `LoginEvent.version` 严格后缀 `;forge-gui-cancel=2`，支持 v1 的撤销能力；不向真正旧主机主动发送无法识别的 ReplyEvent。ready / barrier / cancel / clock 走既有控制帧，校验当前认证连接、请求 ID 和对局 ID，不能信任客户端自报玩家或耗时。
8. 限时远端请求独立于旧 ReplyPool 存活，断线不是 null 答案，重同步完成后重放；旧连接答复、重复 close、迟到 ready、已结束对局的 clock 更新不能影响新请求/新局。仍不提供杀进程恢复、房主迁移、服务端代算或恶意修改客户端的防作弊保证。
9. 桌面确认、战斗伤害和通用数量分配必须走 `callInEdtAndWaitChoice`，不能吞取消异常当作“否”。揭示/通知是 NOTICE 选择，原玩家离局时结束该提示，不把纯告知委派给别人；广播遍历玩家快照，避免离局引发集合并发修改。
10. 战斗伤害按每个生物建立 `enterCombat` 边界，只清除失效来源/目标的伤害分配，保留其他存活玩家的合法分配。清理步骤弃牌属于离局玩家自身义务，不能让另一玩家替他弃自己的牌。
11. 超时取消后，最外层选择在获准输入动作排空后统一 `endTempShowCards()`，再执行离局；不在定时器或同玩家的内层等待提前清理，以免误清父选择仍拥有的临时可见牌。此处修复了移动端清理弃牌超时后仍残留 8 张临时展示牌的 P2。

## 历史开发记录：每位玩家单局累计操作时钟

### 2026-10-10：计时与待决请求基础层

新增 PlayerOperationClock、PendingPlayerDecision、PlayerDecisionSession 及对应专项测试。它们目前尚未由生产对局调用，不改变现有 AFK 或断线行为，也没有开放计时建房设置。

- PlayerOperationClock 用单调纳秒时钟按玩家累计；begin 创建尚未扣时的请求，ready 标记已可操作，complete 原子判断正常/超时/失效。嵌套 ready 请求按时间区间并集收费，不叠加时长；显示毫秒向上取整，内部不丢弃短操作耗时。
- 断线期间已存在和随后创建的待决请求继续计时；重连只更新连接标志，不重置额度。startGame 重置，closeGame 使旧令牌失效。
- PendingPlayerDecision 明确区分 ANSWERED / TIMED_OUT / CANCELLED，正常 null 答案仍是 ANSWERED，不把取消伪造为玩家选了 null。结束时完成等待并尝试调度仅属于该请求的 UI 清理回调；取消发生在 UI 创建前，随后创建的旧 UI 也会尝试调度清理。调度或回调失败可能留下 UI，不保证自动恢复。
- PlayerDecisionSession 校验请求玩家身份、游戏代次和请求 ID；tick 先终止超时玩家的待决选择，再返回带游戏代次的出局事件，其他玩家的请求不受影响。这里仅返回事件，不直接并发修改 Game 或执行 concede。
- UI 调度器必须异步投递，不得在持有调用方锁时等待 UI。调用方要先验证网络答复类型和合法选择范围，player ID 从已认证连接取得，不能信任包内自报玩家。
- 独立第三轮通过两端编译、Checkstyle 和 28 项指定测试，但故障注入发现 UI 拒绝投递可中断批量取消并丢失超时事件，因此第三轮不予验收。修复将 UI 投递/清理回调的 RuntimeException 与请求完成隔离；每个请求保留 dismissalFailure 供界面适配器诊断，禁止在规则线程重试操作已销毁界面。新增正式回归覆盖 tick/startGame/closeGame、同步/异步回调失败、拒绝投递和正常答复不受清理失败影响。
- 同一独立测试任务第四轮复测通过：两端编译、Checkstyle、6 类 36 项 TestNG（计时 11、待决请求 8、会话 10、既有回归 7），4 个原失败场景与共 11 组独立故障/竞争验证通过，含 600 次 reset 竞争。详见 dist/independent-network-tests/round4/independent-test-report.txt；原第三轮缺陷证据保留。这里只验证基础层，不是生产对局验收。

### 2026-10-10：客户端弹窗取消路径

- GuiRequestScope 将一个客户端远程选择与其 UI/等待绑定；FThreads 传递并恢复请求上下文，普通未绑定的任务显式清空上下文，避免 Swing 嵌套事件循环沿用另一请求身份。
- GameClientHandler 为有返回值的请求及阻塞消息窗口创建作用域。连接失效、handler 移除、本局 finishGame 只撤销本 handler 的尚未完成选择；GameProtocolHandler 不为这些取消发送 null/迟到 ReplyEvent，也不弹出“反射调用失败”错误框。服务器侧 ReplyPool 断线策略本轮未更改。
- WaitCallback 在作用域取消时释放等待并抛出明确的 GuiRequestScope.Cancelled；没有作用域的单机行为保留，正常 null 答复仍合法，重复 callback 不再覆盖第一次答复。UI 创建抛错也会释放等待，不再永久阻塞。
- 桌面和移动 FDialog 将自己的关闭动作登记到请求，取消只调度该实例的关闭；尚未显示的旧窗口不再弹出。桌面取消非栈顶窗口按实例移除；移动延迟隐藏不重复扣减打开窗口计数。清理 RuntimeException 记录在作用域并即时记录日志（含异步失败），不能据此保证窗口已成功关闭。
