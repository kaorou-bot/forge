# 冒险模式中文长句换行

## 问题与范围（2026-11-03）

用户截图为地图冒险 NPC 对话，头像右侧正文越过右边框。实际台词键为
`adv.main_story_spawn.69.d.n11.text`，以“这些是挑战币。山德拉的施法者……”开头。
`MapDialog` 已启用 wrap，正文宽度为 250 减头像 30，即 220；缺失的不是译文。

Textra 0.8.2 的断行表以空格、连字符等为主，连续中文没有断点。另有任务列表、
任务名及阶段名启用 wrap 却未约束单元格宽度，通用提示框也可能被长句撑宽。

## 实现

- `AdventureText` 仅在显示文本中加入 U+200B 断行机会；保留英文词、数字、显式换行、
  标点避头尾、颜色/图标标签及打字控制 token。不会改写语言资源、玩家输入或存档。
- 为缺少 U+200B 的字体添加零尺寸、零 advance 字形，共用已有纹理，不新增 GPU 资源。
- `Controls` 的普通标签、文本按钮及逐字显示控件统一接入；按钮文本读取不暴露断行符。
- `AdventureTypingLabel` 在变量替换后、事件索引登记前规范化显示文本，不能只在
  `Font.markup` 阶段插字符，否则事件与可见字位置会错位。
- 逐字更新期间将 U+200B 的间隔乘数临时设为 0，finally 恢复原配置（含原本不存在的情况），
  不让不可见断点减慢对话，不永久更改其他控件的配置。
- 宽度变化或文本更新后，从已解析显示文本重建 workingLayout，不 restart、不重复触发事件。
  不能依赖上游 targetWidth 判断：act/setSize 会提前改该值；也不能重复对旧行调用
  regenerateLayout，因为旧换行的透明占位可能累积，造成实际可见字越界。
- `QuestLogScene` 约束任务列表及详情宽度；`UIScene` 约束通用提示正文宽度，长文本自动换行。

本轮未更换字体、缩小字号、修改剧情、更新版本号或发布服务器。

## 验证

独立测试任务 `01a12110-42fb-7a42-97a8-a074bf5df870` 的 Round38 r2 最终 66 项通过：
33 项换行回归及 33 项既有字体、术语、地图、任务、空套牌回归；编译和 Checkstyle 通过。

新增 `AdventureTextWrappingTest` 用真实 BMFont/Textra/scene2d 表格和按钮，模拟 GPU 上传及 Batch。
通过真实 drawGlyph 的非透明绘制顶点验证 120/220/300 宽度、截图完整台词+头像、文本更新、
连续宽窄重排、显式换行、逐字时间、变量/事件/等待/效果标签、进行中重排和跳过打字等路径。
库产生的透明行尾占位会影响测量总宽，不能单凭 Line.width 将其判成可见越界；
也不能忽略透明占位的 advance，必须核对实际可见顶点和字符顺序。

证据：固定开发树 `dist/independent-network-tests/round38-adventure-wrap/final-report.txt`；
权威汇总为 `r2-all-adventure-reports/TEST-TestSuite.xml`，不要累计其中旧运行的单类 XML。
测试期间产品源码哈希不变，测试结束后已交还工作树与缓存。
